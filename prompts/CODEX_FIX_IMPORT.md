# Codex 실행 프롬프트 — 시험지 문항 크롭/OCR/그림 의미 구조 검수

현재 프로젝트의 `data/raw/2025_A.pdf`, `2025_B.pdf`, `2026_A.pdf`, `2026_B.pdf`와 `data/processed/`, `overrides/layout_overrides.json`, `scripts/ingest_pdfs.py`, `docs/DATA_CONTRACT.md`를 확인해라.

목표는 시험지 원문을 **재생성하거나 예쁘게 다시 그리는 것**이 아니다. 문제 원문을 보존하면서 **AI가 읽고 참조할 수 있도록 구조화**하는 것이다.

## 최우선 검수

1. 연도별 A 12문항, B 11문항, 총 46문항 **실제 존재 및 내용** 대조.
2. 2단 편집(좌/우), 여러 페이지, 문항 제목/번호 옆에 다른 문제가 섞인 경우 모두 찾아 수정.
3. 모든 문항의 시작·종료 범위와 원본 PDF page/bbox 기록. crop 누락/겹침 교정.
4. 수식/표/논리회로/네트워크 도식/코드 블록을 눈으로 살펴 구조적으로 정확히 표현.
5. OCR 문자 오류를 교정하되 원본 문자열은 별도로 유지. 표와 코드 들여쓰기 특히 주의.
6. 이미지 crop을 모델에 직접 보내 필요시 아래의 semantic JSON 필드를 채울 것.

## 그림 설명(매우 중요)

문항별 `analysis.visuals`에 **이미지의 실물 묘사**를 저장하라.

- 보이는 요소: 노드, 연결선, 수치, 화살표, 좌표, 표의 행/열, 기호, 코드/수식 등.
- 이 요소가 문제에서 어떤 정보로 제공되며 무엇을 계산/설명해야 하는지.
- 확인하지 못한 기호·값은 추측하지 말 것.
- `verified/inferred/uncertain` confidence로 구분.
- 해설·정답을 적어 넣지 말 것(나중에 사용자가 문제를 풀 때 AI가 요청 시 해설).
- AI가 이미지를 읽을 수 있도록 crop 이미지를 **보존하고** semantic 텍스트와 병행 제공.

문항을 다음 필드 중심으로 구조화:
- `stem`: 질문 내용
- `given`: 주어진 조건
- `condition`: 풀이의 제약
- `code`: 코드(들여쓰기 유지)
- `table`: 표/셀 관계
- `formula`: 수식
- `diagram`: 그림/회로/그래프
- `task`: 요구된 답안 항목/배점

## 수정 방식

- 원본 PDF에는 손대지 말 것.
- 실질적인 crop 경계 오류는 `overrides/layout_overrides.json`에 해당 문항만 보정하고 `ingest_pdfs.py`를 재실행.
- 자동 분리 코드의 일반화 가능한 버그만 코드를 변경.
- 사용자의 개인 복습 노트/대화는 절대 수정·삭제하지 말 것.
- 처리된 문항은 `verified`로, 불확실한 문항은 `needs_review`로 분리.
- 모든 파일을 실제로 렌더링하여 확인하고 누락이 있으면 수정을 반복하라.

## 산출물

1. 원본 PDF 기반 문항 이미지 46건(문항당 여러 crop 가능).
2. 46개의 `question.json`(비어 있는 부분은 정직하게 표시).
3. `corpus.jsonl` + 검색/검수용 `index.html`.
4. 통계: 검수 완료/검수 필요, 누락, 중복, 그림·표·코드 품질 문제.
5. Codex 웹앱이 이 문항 JSON을 import하는 엔드포인트/스크립트와 실제 import 검증.

중간 과정에서 인증·권한 등으로 막힌 외부 작업 외에는 가능하면 스스로 끝까지 처리하라. 단, 검수하지 않은 문항을 완료로 보고하지 마라.
