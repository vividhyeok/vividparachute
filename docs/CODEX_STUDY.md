# Codex에서 공부하고 서재에 반영하기

웹에는 질문 입력이나 AI 모델 호출이 없다. 같은 `vividparachute` 프로젝트에서 새 Codex 채팅을 열고 `2026 A 3번에서 ReLU를 어디에 적용하는지 힌트만 줘`처럼 물으면 된다. 프로젝트의 `AGENTS.md`가 답변과 기록 절차를 지정한다. 다른 프로젝트에서도 `vividparachute-study` 사용자 스킬을 사용할 수 있다.

## 조회

```powershell
npm run study -- context "2026 A 3번"
npm run study -- context "활성화 함수"
```

문항 조회 결과에는 실제 원본 이미지의 `absolutePath`, 원 추출/교정 텍스트, 기존 개념 본문·버전, 질문 이력, 문제 연결이 포함된다. Codex는 이미지들을 직접 읽고 질문에 답한다. 모호한 번호는 추측하지 않는다.

`transcription`이 있으면 원본과 대조한 구조화 전사다. 코드·표·수식·도해 참조와 도해별 관찰 설명을 포함한다. 그림 설명은 문제에 쓰인 원문 문장이나 해설과 혼동하지 않는다. 웹의 `검수 전사 보기`는 실제 원본 도해 영역을 함께 보여 준다. `raw_text`는 종전 추출본이므로 코드 줄 순서가 섞이거나 표·그림이 누락될 수 있다. 검수 전사가 있어도 학습 답변 전에는 원본 이미지를 확인한다.

## 저장

JSON을 `data/private/inbox/` 등에 UTF-8로 작성하고 아래 명령을 실행한다. 스키마는 `lib/types.ts`의 `StudyEntrySchema`다.

```json
{
  "entryId": "unique-stable-id-for-this-conversation-turn",
  "questionId": "info-computer-2026-A-3",
  "question": "사용자가 실제로 질문한 원문",
  "answer": "Codex에서 실제로 제공한 답변",
  "source": "Codex 학습 채팅 (알 수 있는 경우 채팅 식별자)",
  "concepts": [
    {
      "slug": "existing-slug-or-new-name",
      "title": "개념 이름",
      "aliases": [],
      "body": "기존 내용을 통합해 다시 편집한 Markdown 완성 본문",
      "context": "이 문제에서 이 개념이 필요한 맥락",
      "expectedVersion": 0
    }
  ],
  "reflections": []
}
```

예시는 입력 필드 안내일 뿐 실제 학습 기록으로 저장하지 않는다. 신규 개념은 버전 0, 기존 개념은 `context`에서 조회한 현재 버전을 쓴다. 같은 개념을 여러 번 새로 만들거나 답변을 통째로 이어 붙이지 않는다. 원문 질문과 설명은 메시지로 보존하고, 전과는 객관적 지식만 간결하게 통합한다. 사용자가 직접 말하지 않은 오답·사고·이해 상태를 만들어 저장하지 않는다. `reflections`는 사용자가 명시한 내용만 `thought/confusion/mistake/review/memo`로 분류한다.

```powershell
npm run study -- record "data/private/inbox/entry.json"
```

저장과 개념 변경은 하나의 DB 트랜잭션이다. 같은 `entryId`의 동일 요청은 중복 저장하지 않는다. 버전 충돌 시 원본을 다시 조회해 통합하고 재시도한다. 저장 후 자동으로 비공개 Blob에 게시한다. 동기화만 실패하면 로컬 기록은 남고 명령은 실패 상태를 알린다.

### 문항의 풀이 상태

사용자가 해당 문항을 다 풀었다고 명시한 경우, 동일한 `record` 입력에 선택 필드 `"progress": "completed"`를 넣는다. 완료를 취소하고 다시 진행 중으로 바꾸라는 명시적 요청에는 `"progress": "in_progress"`를 넣는다. 이 필드는 `questionId`가 있을 때만 허용하며 메시지·개념과 같은 트랜잭션으로 저장·게시된다. 별도 상태 변경을 요청하지 않은 일반 학습 기록에서는 필드를 생략하여 기존 완료 상태를 보존한다. 설명 생성·정답 제시·추측만으로 완료를 기록하지 않는다.

기출 전체 목차와 `한눈에·검색`에서 풀이 상태를 색으로 구분하고 호버·키보드 포커스 시 뜻을 보여 준다. 터치 화면에서는 ⓘ 안내를 펼친다. 최근 공부는 문항별 메시지·메모·명시적 상태 기록 시각으로 정하며, 개념 편집 시각이나 단순 페이지 열람으로 바꾸지 않는다. 열람은 브라우저 로컬에만 보관하여 `열어봄`으로 구분한다. 저장 기록이 없을 때는 `기록 없음`으로 표현하고 실제 미풀이를 단정하지 않는다.

```powershell
npm run sync
```

웹은 저장소 버전을 약 3초마다 확인해 열린 페이지를 갱신한다. PC가 꺼져도 마지막으로 게시한 내용은 배포된 서재에서 읽을 수 있다. 새 기록을 올릴 때는 이 PC의 Codex/로컬 DB를 사용한다. Codex 앱의 모든 과거 채팅을 몰래 읽거나 상시 감시하는 서비스는 아니다.

## PDF

웹의 `PDF 다운로드`는 그 시점의 원문·통합 개념·복습 노트·메모를 반영한다. 기출 PDF는 원본 크롭의 숨은 OCR 텍스트층과 읽을 수 있는 복습 노트 페이지를 포함한다. 개념 PDF는 본문·관련 기출·메모를 포함하며, 질문·답변 대화 목록은 나열하지 않는다. 한글과 수식은 폰트를 포함한 선택 가능한 텍스트다. 원문 OCR의 오독 가능성과 전사 검수 상태는 보존한다.

Codex에서도 직접 만들 수 있다.

```powershell
npm run study -- pdf "2026 A 3번" "output/pdf/2026-A-3.pdf"
```

전체 학습 노트는 `npm run study -- pdf all "output/pdf/study-notes.pdf"`로 내보내거나 웹 PDF 버튼 옆 메뉴에서 받는다. 개념 본문은 중복 없이 한 번씩, 문항별 메모와 학습한 기출의 OCR 원문은 함께 수록한다. 대화 원문을 PDF에 나열하지 않는다. 웹의 손글씨·형광펜·공책 서식을 인쇄용으로 반영하고 본문 텍스트 검색을 유지한다. 과목별 선택은 README에 기록한 향후 방향이며 현재 설정 UI를 만들지 않는다.

필기는 다운로드한 PDF를 평소 필기 앱에서 한다.

## 배포와 개인정보

소스 코드는 공개 GitHub, 기출/학습 기록은 Blob 파일 저장소에 둔다. 사용자가 로그인 없이 읽는 방식을 선택했으므로 배포 웹의 기출·질문·개념·메모와 PDF는 공개 접근할 수 있다. 파일 저장소의 PRIVATE 설정은 서버가 파일을 읽는 방식일 뿐, 별도 DB 서버나 웹 로그인을 뜻하지 않는다. 로컬 비밀값은 `.env.local`에만 있고 출력하거나 커밋하지 않는다. 클라우드 동기화는 앱 코드 배포와 별개여서, 새 학습 기록마다 빌드가 필요하지 않다.

## 설명문 표시 원칙

웹과 PDF는 대화 목록 대신 연결된 개념의 통합 설명문을 표시한다. 질문과 답변 원문은 저장하되 본문에 나열하지 않는다. 사용자가 명시한 혼동을 해소하는 용어 구분은 설명문 안에서 굵게 강조한다. 대화형 표현이나 “Codex에서 정리한 내용” 같은 표제를 쓰지 않는다.

## 전과와 복습 노트 작성 원칙

전과는 보편적인 지식을 상위 개념 → 핵심 관계 → 필요한 세부 사항 순으로 통합한 개념서다. 질문마다 파편을 추가하거나 세부 지식을 망라하지 않는다. 블로그식 도입·대화체·장문의 해설을 피한다. 개념의 성격에 따라 짧은 정의, 비교표, 수식, 코드, 흐름·도식을 선택한다. 기출 우측도 같은 노트 형식으로 구성하고 사용자가 명시한 혼동을 해소하는 용어·차이를 굵게 강조한다. 손글씨는 강원교육새음체, 강조는 절제된 밑줄·형광펜 표현을 사용한다.

전과 첫 화면과 `한눈에·검색`은 개념을 질문 목적별로 묶어 보여 준다. 제목·별칭은 개념을 식별하도록 정확히 유지하고, 본문은 상위 구조와 핵심 관계가 드러나는 짧은 도입 및 의미 있는 소제목으로 작성한다. 미리보기를 위해 개인 원문이나 문제 정답을 새로 만들어 넣지 않는다. 분류를 위한 별도 모델 호출이나 코드 내 개인 학습 내용 복제는 하지 않는다.

### 누적 노트의 이해 순서

새 질문이 생기면 복습 노트 전체를 다시 읽고, 이미 다룬 범위 안에서 **기초 개념 → 핵심 원리 → 관계·구분 → 문제 적용**의 이해 순서로 통합 재편집한다. 새 내용은 이해에 필요한 위치에 넣고 중복·뒤늦은 정의·끊긴 연결을 정리한다. 질문 시각이나 추가 순서를 학습 순서로 삼지 않는다. 처음부터 다시 읽어도 앞에서 설명하지 않은 개념을 전제로 하지 않도록 하되, 사용자가 묻지 않은 심화 내용이나 선수 지식을 망라하지 않는다. 개념 사이의 연결·배치도 함께 검토한다. 학습 대화 원문은 그대로 보존한다.
